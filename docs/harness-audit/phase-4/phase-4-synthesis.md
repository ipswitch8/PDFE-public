# Phase 4 — UI/E2E & Process/Governance Critique (Synthesis)

Audit of the native-UI/E2E layer (skip-guard, matrix over-claim, visual-oracle blindness) and the process/governance layer (gate integrity, GAP-A15, mutation/coverage floors, flaky/DoD/DCA). FIND-AND-DOCUMENT only.

## Headline findings

- GOOD: the gate-reliability fix is REAL — verdicts derive from artifacts + parsed JUnit XML, not prose; no forgery allow-list; GAP-A15 defended in CI (XML sum-of-failures, not exit code).
- HOLLOW STANDING GATES: the CI mutation-kill gate is green-by-construction (3 curated mutants, all pre-fixed) while phase-3's real 16-mutant run found 10 survivors incl. a redaction confidentiality regression; coverage floor unenforced; DCA loop decorative; DoD absent.
- META: every quality gate is decoupled from the merge — all CI is nightly/dispatch-only since 2026-07-20, so nothing blocks a bad commit at commit time.
- UI PERMASKIP WALL: ~472 of the ~1018 UI skip sites are silent-zero-protection (gap_a14 UIA-hang), gating an estimated ~300 of ~450 UI test functions from running ANY behavioral assertion in CI.
- MATRIX OVER-CLAIM: UI-matrix 'pass' is a runtime CSV rebuilt from a one-off interactive run; 236 dialog rows are green on objectName-present-in-.cpp alone, 131 act_* rows green on pipe-fired-no-effect.
- VISUAL ORACLE EXISTS BUT SHALLOW: PrintWindow/SSIM/pixel_diff/golden exist but goldens self-seed, thresholds relaxed, and all of it sits behind the gap_a14 skip wall — so mirrored/wrong-zoom canvas, tofu glyphs, wrong icon, garbled dialog, white/half-size edited text stay invisible (the shipped content-stream bug class, one level up from phase-1).

## Ranked process findings

- **[High] CI trigger posture (meta-finding)** — EVERY quality gate is decoupled from the commit that would introduce a regression. As of 2026-07-20 all PDFE CI is nightly/workflow_dispatch ONLY — push/PR auto-triggers were removed to protect the single self-hosted runner. Windows+Linux full validation run nightly; mutation-kill, governance (DCA, mutation dry-run, matrix-health), and windows-fuzz run on-demand or nightly and never block a merge. The gates are mechanically real but nothing fails a bad commit at PR/merge time; a regression surfaces at best the next nightly, at worst only when a human dispatches. (windows-validation.yml:23-34; mutation-kill.yml:23-24; governance.yml:24-25; docs/harness-audit/census.json:452)
- **[High] Mutation gate is green-by-construction** — The standing CI mutation manifest (mutants.json) has 3 mutants, all already-fixed lines curated to be killed, so mutation-kill.yml can only report 100%. Phase-3's real 16-mutant run found 10 surviving mutants (37.5% kill-rate) — including a redaction single-revision confidentiality regression and multiple invisible-render text-edit defects — NONE of which are represented in the standing manifest. The gate that is supposed to be the standing defense against false-green oracles does not exercise any known false-green oracle. (tools/gate/mutants.json (3 mutants); docs/harness-audit/phase-3/mutation-report.md:5-96 (10 survivors))
- **[High] Escaped-defect / DCA loop not enforced** — The harness has been reactive since inception: of 72 mined bug-fixes, 70 escaped to a human before any test existed (oracle 41 / coverage 15 / input-domain 8 / process 6). The designed remedy — the escaped-defect->DCA->class-test loop — is fully implemented (check_dca.py + check_dca_presence.py) but only runs inside governance.yml, which is workflow_dispatch-only and runs check_dca_presence only when a base ref is manually supplied. Result: a defect fix can (and by the 1-record history, does) ship with no DCA and no class-level test, exactly the reactive posture the loop was meant to end. (docs/audit/README.md:34-35,51; governance.yml:51-58; docs/audit/dca/ (only 0001-*.md))
- **[Medium] Coverage floor unenforced** — OpenCppCoverage->Cobertura is best-effort: continue-on-error:true, silently skipped when the tool is absent on the runner, and gated by NO floor. It produces an artifact but can never fail the build, so coverage regressions are invisible to CI. (windows-validation.yml:346-374)
- **[Medium] macOS validation is a thin subset** — macos-validation.yml runs only PreflightOpen.*/PreflightXPlatform.* (~a handful of isolation-boundary tests), not the full suite, so the macOS lane provides almost no regression coverage despite being one of three advertised platforms. (macos-validation.yml:118-120)
- **[Low] No formal flaky quarantine ledger** — Rerun-on-failure is a sound policy, but known-flaky tests (PerfStressTest.TenThousandAnnotationsOnePage, MainWindowIntegrationTest.ZoomComboExists) are tracked only in inline comments. There is no machine-readable quarantine/xfail registry, so a test degrading from reliable to flaky is not tracked as a first-class signal and reruns can mask a slowly-worsening test. (census.json:451; windows-validation.yml:291-304)
- **[Low] Judgment-gate verdict is honor-system (bounded)** — karen/validator/security-audit emit their PASS artifact via emit-gate-verdict.sh with no independent evidence of their own; the hook only re-checks the test-runner XML. The red-XML veto prevents signing off a phase with failing tests, so the exposure is limited to a judgment gate falsely blessing a phase whose tests are green but whose acceptance criteria were not truly met. (~/.claude/hooks/phase-gate.sh:218-241 (derive_verdict, judgment-gate branch))
