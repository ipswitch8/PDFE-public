# Content-Stream State-Continuity — Coverage Narrative

Pipeline: **content-stream-continuity** (Phases 1–4). Companion to `RTM.md`.

## 1. The bug class

Every PDFE feature that draws onto an existing page does so by **appending an
operator fragment to the page's `/Contents`** — inline text edits, reflow /
alignment, headers & footers, watermarks, image insert/resize/rotate/crop, and
the TRE text-reconstruction writer. Appended content runs *after* whatever the
page's original content stream already executed. If that original stream leaves
a graphics- or text-state operator **live at the top level** — a negative `Tz`,
an unbalanced `q`, an N-up `0.5 … cm`, an invisible `3 Tr`, a stray CMYK or white
fill — the appended fragment **inherits it**. The injected element then renders
half-size, mirrored, invisible, mis-coloured, or off-page.

This is an *inbound* leak (the host page corrupts our injection), the mirror
image of the *outbound* leak documented in
`docs/content-stream-state-continuity-audit.md` (our injection corrupting the
host). Both share a root cause: injectors assumed a clean, identity graphics
state that a hostile or merely unusual page does not provide.

### Why the existing suite never caught it

Text extraction (`fz_stext`) recovers the **logical** characters regardless of
how they rendered: Tr-3 invisible text reads as present, white-on-white reads as
present, half-size reads as present, mirrored text reads as present (with a
flipped quad). Any oracle built on extracted text is **blind** to the entire bug
class. Detection requires a **pixel oracle** (ink present in the rendered ROI —
catches invisible / white / off-page) plus a **glyph-quad oracle** (upright,
correctly-sized — catches mirror / half-scale). The pre-existing fixtures also
only ever carried *benign* ambient state, so the hostile path was never
exercised.

## 2. The adversarial-ambient corpus — the missing test layer

Phase 1 built the test layer the suite never had: a corpus of fixtures
(`tests/fixtures/adversarial_ambient/`, generated by `gen_aa_corpus.py`) where
each PDF's `/Contents` leaves **exactly one** hostile ambient operator live,
with a pre-existing `KEEPME` neighbour drawn safely in its own `q … Q`. Two
fixture families — text (`aa_<op>.pdf`) and image (`aa_img_<op>.pdf`) — cover
the eight operators `neg_tz, tc, ts, tr, white, cm, dangling_q, cmyk`.

The **72-cell render probe** (`tests/test_content_stream_adversarial_ambient.cpp`,
`AdversarialAmbient.*`) drives all **9 injectors × 8 hostile ops** headlessly:
inject → save → reopen → render → apply the pixel + glyph-quad oracle, recording
`injected_ok` and `neighbor_ok` per cell into a JSON gap register. It is a
*measurement instrument* — a corrupt cell is data, not a red test — so discovery
and remediation stay cleanly separated.

## 3. Discovery result

The Phase-1 probe found **3 confirmed CTM bugs** across the 72 cells: the three
**text** injectors — **AlignmentInjector**, **HeaderFooterEngine**, and **TRE
`PdfContentWriter::writeTextBlock`** — all rendered their injected text
**half-size** under the N-up `0.5 0 0 0.5 0 0 cm` ambient transform (the `cm`
column). The image injectors were already immune: they appended through
`appendContentIsolatingAmbientCtm()`, which brackets the existing content so the
CTM is restored to identity before the fragment runs. The text injectors used a
state preamble that resets `Tz/Tc/Tw/Ts/Tr` + fill colour but **cannot** reset
the CTM (a `cm` *multiplies* — it cannot replace).

## 4. The systemic fix

Rather than patch three call sites, Phase 2 routed all three text injectors
through the **same** shared helper the image injectors already used:
`core/PageContentGuard.h::appendContentIsolatingAmbientCtm()`. It brackets the
existing page content in `q … Q` (the leading `q` carries a `%PDFE-CTMGUARD`
sentinel comment) so the outer `Q` restores the page-initial identity CTM before
any appended fragment executes, and each fragment is itself balanced. The
sentinel makes the guard **idempotent**: a later injector detects the existing
guard and appends after it instead of nesting a second bracket. Phase 2's
hard-assertion suite (`tests/test_content_stream_ctm_reset.cpp`, `CtmReset.*`)
promoted the three corrupt `cm` cells to EXPECT/ASSERT oracles; the gap register
now reports `confirmed_corrupt=0`.

**Phase 4** closed the one gap karen flagged against the shared helper: it is
correct for a *single* injector, but is the sentinel truly idempotent when **two
different injectors** run on the same page? `MultiInjector`
(`tests/test_content_stream_multi_injector.cpp`) chains AlignmentInjector →
HeaderFooterEngine on the hostile `aa_cm.pdf`, then asserts (1) **exactly one**
`%PDFE-CTMGUARD` stream survives in the page-0 `/Contents` (no double-bracket),
(2) **both** injected lines render full-size + upright + on-page, and (3) the
`KEEPME` neighbour is uncorrupted.

Three mutation kills confirm the oracles actually bite — each names the test that
went RED when the fix was reverted:

| # | Mutation (revert the fix) | Test that RED'd | Phase |

| 1 | Revert AlignmentInjector's delegation to `appendContentIsolatingAmbientCtm()` (bare append inherits the 0.5x CTM) | `CtmReset.AlignmentInjectorFullSizeUnderAmbientCm` (sizeRatio ≈ 0.5) | 2 (karen) |

Mutation #3 evidence, Phase 4: with `guarded` forced false, rebuilt serially and
re-ran — the guard-count oracle failed with `guards=2`. Reverted, rebuilt,
re-ran green. This proves the idempotency assertion is load-bearing, not
decorative.

## 8. Residual / known limitations (honest scope)

- **Multi-injector column is directly tested only for AlignmentInjector →
  HeaderFooterEngine.** The other seven injectors share the *identical*
  `appendContentIsolatingAmbientCtm()` code path, and mutation #3 proves the
  idempotency branch for that single path, so they are covered *by
  construction* — but no test exercises every pairwise ordering (e.g. image
  insert then watermark then reflow). A full N×N chaining matrix was judged
  low-value given the single shared code path; this is a deliberate scope call,
  not an oversight.
- **The probe's `cm` fixture uses one N-up SCALE (0.5×).** Other imposed
  *scale values* (0.25×, 2×, non-uniform) are not enumerated. The guard
  neutralises *any* ambient CTM by design (it restores identity, independent of
  the specific matrix), and the hard-assert `CtmReset` cells confirm the 0.5×
  case, but alternative scales are not individually fixtured.
