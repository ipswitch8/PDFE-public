# Internationalization (i18n) — PDFE

## Scope (current)

**The translation mechanism is in place; PDFE ships English only.**

There are no compiled application translation catalogs (`app_<locale>.qm`)
bundled with releases today. At runtime the app-level translator load fails
gracefully and the UI falls back to the English source strings. Qt's own base
translations (`qtbase_<locale>.qm`) are still loaded when the host Qt provides
them, so standard Qt dialog buttons (OK / Cancel / Yes / No), the file dialog,
etc. localize on a translated system without any PDFE work.

This is a deliberate, documented scope decision (finding R2-22): the
infrastructure exists so that adding a language is a **build-time / translation**
task with **no C++ change required**.

## Runtime mechanism

`pdfe::app::installTranslations()` — declared in `src/app/Translations.h`,
implemented in `src/app/Translations.cpp`, called once from `src/main.cpp`
immediately after `QApplication` is constructed:

```cpp
bool installTranslations(QCoreApplication& app,
                         const QString& locale = QLocale::system().name());
```

It installs up to two `QTranslator`s, each only on a successful load:

1. **Qt base** — `qtbase_<locale>.qm` from
   `QLibraryInfo::path(QLibraryInfo::TranslationsPath)` (Qt's own translations
   directory).
2. **PDFE application** — `app_<locale>.qm`, searched in this order:
   1. Qt resource path `:/i18n` (if a future build embeds `.qm` via an
      `i18n.qrc`),
   2. `<application-dir>/translations`,
   3. `<application-dir>`.

Missing `.qm` files are non-fatal: the corresponding translator is simply not
installed (no crash, no log spam), leaving English in place. The function
returns `true` **only** when the application-level `app_<locale>.qm` was found
and installed; `false` is the normal, expected result for the shipping
English-only build. Installed translators are parented to the `QCoreApplication`
so they persist for its lifetime.

## Where `.qm` files are loaded from at runtime

| Order | Location | Purpose |
|------:|----------|---------|
| 1 | `:/i18n/app_<locale>.qm` (Qt resource) | embedded catalogs (optional, not currently built) |
| 2 | `<appdir>/translations/app_<locale>.qm` | install/CPack-staged catalogs |
| 3 | `<appdir>/app_<locale>.qm` | dev run-from-build-tree fallback |

Qt base catalogs come from Qt's `TranslationsPath` (outside the table above).

## How to add a locale

Source catalogs live in `translations/` (`app_en.ts`, `app_fr.ts` seed the
pipeline). The workflow is the standard Qt Linguist round-trip:

1. **Extract / update translatable strings** from source into a `.ts`:

   ```
   lupdate src/ -ts translations/app_<locale>.ts
   ```

   `lupdate` scans `tr()` / `QCoreApplication::translate()` / `QT_TR_NOOP`
   calls. Run it whenever UI strings change.

2. **Translate** in Qt Linguist (or edit the `.ts` XML directly):

   ```
   linguist translations/app_<locale>.ts
   ```

3. **Compile** `.ts` -> binary `.qm`:

   ```
   lrelease translations/app_<locale>.ts -qm translations/app_<locale>.qm
   ```

4. **Deploy** the `.qm` so it lands in one of the runtime search locations
   (e.g. `<appdir>/translations/`). When wired into CMake (below), the build
   compiles and stages `.qm` automatically.

No code change is needed for a new locale — `installTranslations()` picks up
`app_<locale>.qm` for the user's system locale automatically. To force a locale
for testing, call `installTranslations(app, "fr_FR")`.

## CMake wiring (translation compilation)

`.ts -> .qm` compilation is **not yet wired into CMakeLists** (English-only
scope). To enable it, add the Linguist tools to the root `find_package` and a
`qt_add_translations` (or manual `lrelease`) rule. See the pipeline report /
`translations/` for the exact lines. The reference form (Qt 6.7+):

```cmake
# root CMakeLists.txt — add LinguistTools to the existing Qt6 find:
find_package(Qt6 REQUIRED COMPONENTS Widgets Test PrintSupport Network Svg LinguistTools)

# src/app/CMakeLists.txt — compile app_<locale>.ts and stage app_<locale>.qm
# next to pdfe.exe (search location #2 above):
qt_add_translations(pdfe
    TS_FILES
        ${CMAKE_SOURCE_DIR}/translations/app_en.ts
        ${CMAKE_SOURCE_DIR}/translations/app_fr.ts
    QM_FILES_OUTPUT_VARIABLE pdfe_qm_files
)
# (optionally install(FILES ${pdfe_qm_files} DESTINATION bin/translations))
```
