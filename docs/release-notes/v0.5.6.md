# PDFE v0.5.6

A release over v0.5.5 with fixes for the dark theme, form filling and
signing, and a new way to place a signature image without a certificate.

## Dark theme

- **Toolbar icons are visible in the dark theme.** They used to be dark grey
  on a dark toolbar, close to invisible. Icons now take their colour from the
  current theme, and they follow a switch between Light, Dark and System
  without restarting. Disabled icons now look different from enabled ones.
- **The float and close buttons on every panel's title bar** follow the theme
  the same way. In the dark theme they were dark grey too.

## Form fields

- **Form fields stay fillable after you save.** After File > Save, clicking a
  field with the Form Tool did nothing until you switched tools. It now works
  straight away.
- **Fields in a reopened form can be filled without changing tools.** A
  document opens with the Select tool, which could not fill fields. Clicking a
  fillable field with it now switches to the Form Tool and starts the edit, or
  ticks the box. Signature fields, buttons and read-only fields behave as
  before.

## Signing

- **Create certificate works, and its errors can be fixed.** The form used to
  accept anything, ask where to save, and only then reject an empty Common
  Name, in a message at the bottom of the Sign dialog after the form had
  closed, so no certificate file was created. The new Create Certificate form
  holds the name, organisation, validity, passphrase and output file in one
  place. It checks them when you press OK and stays open with the problem
  shown in the form and the cursor on the field to fix. It adds `.pfx` to the file
  name when needed and does not overwrite an existing file unless you chose
  that file with Browse. The result is shown next to the Create button.
- **Visual signature without a certificate.** The Sign dialog has a new
  option, **Visual signature only (image and date, no certificate)**. It places
  your signature image on the page with "Signed" and the date and time, as an
  image stamp you can undo. **This is not a digital signature:** it does not
  prove who signed and does not detect later changes. No certificate or PFX
  file is needed or used, and the stamp and its properties say it is not a
  digital signature. Placed over an existing signature field, the field stays
  unsigned.

## Annotations

- **Image stamps keep their image.** A stamp placed with the Stamp tool from
  an image was saved as a plain text stamp. It now keeps the image.
- **Undo then Redo of a placed image stamp keeps its image and its text.**
  Before, Redo brought the stamp back without them.

## Known issues

- **An intermittent crash in a tile-rendering test** (GitHub #469). It was seen
  once in the automated test suite and has not been reproduced on demand; no
  user report is linked to it. Still open and tracked for investigation.

## Checksums

The Linux section of this release lists the AppImage, .deb and .rpm with
their SHA-256 values, and each has a `.sha256` file beside it. The Windows
files are added to this release separately.
