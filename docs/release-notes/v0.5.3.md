# PDFE v0.5.3

A bug-fix release over v0.5.2, rolling up the image-insertion and transparency
fixes plus a test-hardening pass. No on-disk format changes; a drop-in update.

## Fixes

- **Inserting an image can no longer crash the app.** The image-insert path had
  no exception boundary, so a MuPDF fault during insert (e.g. an allocation
  failure) terminated the process; it now fails gracefully with a user-facing
  error instead, with a 64-bit pixel index and a null-/non-PDF-target guard.
  (`5a5b0c08`, GitHub #392)
- **Placed-image rotation handle works correctly.** It now rotates to any angle
  (no longer snapping to 90°), each drag is additive from the current
  orientation (fixing a jump to ~180° on the second drag), and the selection
  outline re-syncs to the image after a rotation commits. (`304c2ef6`, GitHub #391)
- **Transparent images embed correctly.** Transparent images of any source
  format keep their alpha (previously dropped for non-ARGB32 inputs such as
  RGBA8888/indexed), colored semi-transparent edges render at the right
  brightness (premultiplied to match MuPDF's convention), and the image-stamp
  path gained the same 64-bit pixel-index guard. (`cc322462`, GitHub #396)
- **Test hardening.** Weak-oracle tests across the interactive-tool/transform
  family were strengthened so a future snap / delta-as-absolute / stale-outline
  regression can no longer pass green, and the missing SelectTool rotate-drag
  test was added. (`558361ec`/`9fee9ec8`/`9f83b0cd`, GitHub #394)

Also includes the Linux-port configure/compile/link/parity work already on
master (GitHub #384 / internal Defect #42, #385).

A reported transparent-signature insert crash that could not be reproduced
(headless or live) remains under open investigation (GitHub #395); no blind fix
was shipped for it.
