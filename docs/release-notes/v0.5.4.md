# PDFE v0.5.4

A bug-fix release over v0.5.3, rolling up a form-field editing overhaul, a large
image-placement correctness batch, and a reconciliation of two independent
form-text-field-visibility fixes. No on-disk format changes; a drop-in update.

## Form fields and text editing

A pipeline of eleven reported form / text-edit / toolbar bugs:

- **Form fields are visible at rest.** A placed field now shows an outline and a
  shaded background when unselected, instead of being invisible until clicked.
  (GitHub #458)
- **Typed text is visible while you type.** The in-progress edit buffer now
  renders live, rather than only appearing after the field loses focus.
  (GitHub #459)
- **Font family, size and colour can be set on a form field** and survive save,
  reopen and undo; a font row was added to the field properties panel.
  (GitHub #460)
- **A placed field can be re-edited and deleted** after content is added and the
  field is clicked away (Delete/Backspace removes a selected field, undoable).
- **The undo-after-edit crash is fixed** — editing a canvas form text field and
  then undoing no longer dereferences a freed page.
- **Esc cancels an in-progress placement** of a form field or annotation.
- **Overflowing toolbars wrap to additional rows** by default instead of hiding
  buttons behind an extension chevron.
- **Edit Text can start a new text run in an empty area** (e.g. to add text to a
  blank line), round-tripping as selectable page text and undoable.
- **Placement tools stay selected** across successive placements, and
- **paste into a form text field** is supported.

Reconciled with an independently developed set of form-text-field-visibility
fixes so the shipped behaviour is a single coherent implementation
(GitHub #462; #458 / #459 / #460), and hardened: the field properties panel no
longer aborts on a destruction-order focus-out, pathologically nested rich-text
(`/RV`) values are bounded before appearance generation, and a NaN colour never
reaches a field's default appearance.

**Known issue:** push-button form fields render with a blank interior (a
pre-existing bug in the bundled MuPDF renderer, not specific to this release;
the less-common push-button field type only). Tracked as GitHub #465.

## Image placement

A correctness batch for image editing and redaction (GitHub #417):

- Moving, resizing, editing, cropping, flipping and rotating an image preserve
  the image's rotation, crop, flips, opacity wrapper, tagging / optional-content
  membership, and other copies of the same XObject.
- The image properties panel and editor actions keep rotation and crop.
- Redaction keeps the rest of an image, honours per-mark redaction methods, and
  Flatten Form stays on its own page.
- Watermark, metadata stripping and extraction preserve the page's state.
- Text-recognition replace and auto-tagging keep the image's placement.
