# PDFE v0.3.2

A bug-fix release. It fixes **"Edit Text" on image-only (scanned) PDFs not saving
the change** — the selected region was OCR'd and shown correctly in the dialog,
but neither edit option made the change visible on the page. A codebase sweep for
the same underlying defect found and closed five more instances. No new features,
no API or on-disk format changes; a drop-in update over v0.3.1.

## Changes

- **Edit Text now lands on the image the page actually draws.** On a PDF whose
  page resources hold several identical-dimension image XObjects (a scanned
  document can hold hundreds of same-size page images in one shared dictionary),
  the write-back resolved its target by pixel dimensions / largest area, which
  ties on duplicates and wrote the composited edit into the wrong image — so the
  change never appeared. The target is now resolved by the content stream's own
  draw operator (`/Name Do`) and placement (CTM), which is unambiguous even
  across identical-size images. (`8ac47ad1`)
- **Page source-DPI no longer tie-breaks arbitrarily** among equal-area images;
  it reports the true page maximum. (`8ac47ad1`)
- **Text edits encode under the correct font resource.** When two font resources
  shared a `BaseFont` name, an edit could be emitted under the wrong one
  (garbled/wrong glyphs); edits now use the font resource the run actually used.
  (`c862b7c7`)
- **The edit now refreshes the view and reports failure.** A successful region
  edit invalidates the page, image, and thumbnail caches so it shows immediately;
  an edit that cannot be committed visibly now surfaces an explicit failure
  instead of silently doing nothing. (`a4882b32`)
- **Overlapping redaction marks select the topmost** (the one you see and
  clicked), not the one underneath. (`117cc878`)
- Regression tests pin each fix, asserting on the rendered page / committed
  content, plus the reproduction fixtures. (`c24924c5`)

Full detail: `docs/audit/fix-tre-writetarget-2026-11-01.md`.
