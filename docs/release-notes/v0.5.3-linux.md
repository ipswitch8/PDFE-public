# PDFE v0.5.3 for Linux

The first Linux release of PDFE. It ships for x86_64 Linux in three forms:

- an AppImage, with an installer script;
- a `.deb`;
- an `.rpm`.

All three carry the same binaries. The `.deb` and `.rpm` are built from the AppImage's own contents.

**This is the Linux release of 0.5.3.** Windows users should take the [v0.5.3 release](https://github.com/ipswitch8/PDFE/releases/tag/v0.5.3), which has the signed installer. That release was built from an earlier commit that did not yet have the Linux port. This one is tagged separately, `v0.5.3-linux`, so that each release points at the exact source it was built from.

## Fixes since v0.5.2

These are the same fixes as in the Windows v0.5.3. All of them came in through GitHub #397.

- **The image rotation handle works properly.** It used to snap to 90°, its outline fell out of step with the image, and every drag after the first jumped to about 180°. Now it takes any angle, consecutive drags add up, and the outline follows the image. (GitHub #391)
- **Inserting an image into a large PDF no longer crashes the app.** The insert path now has an exception boundary, so a MuPDF out-of-memory or other error is reported instead of ending the process. (GitHub #392)
- **Transparent images are inserted correctly.**
  - A transparent image that isn't ARGB32 (RGBA8888, or indexed with transparency, for example) no longer loses its alpha.
  - Semi-transparent pixels no longer render too bright. Insert, stamp and the EXIF-stripping path now write them premultiplied, as MuPDF expects.
  - A very large stamp image can no longer overflow the pixel index. (GitHub #396)
- **The tests behind these features are stronger.** The interactive-tool, transform and image tests now fail on a snapped angle, a delta treated as an absolute value, or a stale outline. They used to pass. (GitHub #394)

One report is still open: a crash while inserting a transparent signature, which could not be reproduced (GitHub #395).

## Linux

Linux is a new platform for PDFE (GitHub #384 and GitHub #398, tracked in GitHub #390). The platform services have native Linux versions:

- the crash handler;
- the sandboxed preflight that checks a document before it opens;
- held temp files;
- fontconfig font lookup.

On Linux, the full GoogleTest suite ran 6,704 tests with 0 failures and 53 skipped:

- 44 test Windows-only behaviour;
- 4 need a font-classifier model file that the test machine did not have;
- 3 need a drive-letter temp path;
- 2 are child-process roles that other tests drive.

Every package below was installed, run (`pdfe --version`) and removed in a clean container:

| package | tested on |
|---|---|
| `.deb` | Ubuntu 24.04, Debian 13 (trixie) |
| `.rpm` | Fedora 41 |
| AppImage, through the installer | Ubuntu 24.04, per-user and system-wide, each run twice |

Requirements:

- x86_64 with glibc 2.39 or newer (Ubuntu 24.04, Debian 13, Fedora 40 or later).
- An X11 or Wayland desktop with OpenGL/EGL.
- These system libraries:
  - fontconfig, with the Liberation and DejaVu fonts;
  - xkbcommon-x11 and xcb-cursor;
  - GL and EGL, including libOpenGL;
  - libSM and libICE;
  - CUPS.

  The `.deb` and `.rpm` pull these in as dependencies, and the installer script installs them for the AppImage.
- FUSE 2 for the AppImage. The installer adds it.

## Install

Pick one. Download the file and its `.sha256` from this release and check the checksum, then follow the matching section.

**Debian, Ubuntu and derivatives (`.deb`)**

```
sha256sum -c pdfe_0.5.3_amd64.deb.sha256
sudo apt install ./pdfe_0.5.3_amd64.deb
```

**Fedora and other RPM distributions (`.rpm`)**

```
sha256sum -c pdfe-0.5.3-1.x86_64.rpm.sha256
sudo dnf install ./pdfe-0.5.3-1.x86_64.rpm
```

Both packages install PDFE under `/opt/pdfe`, with:

- `pdfe` in `/usr/bin`;
- a menu entry that opens PDFs;
- the licence and corresponding-source notice in `/opt/pdfe/share/pdfe`. They are also in `/usr/share/doc/pdfe` where the system keeps documentation.

Remove PDFE with `sudo apt remove pdfe` or `sudo dnf remove pdfe`.

**Any distribution: AppImage with the installer**

```
sha256sum -c PDFE-0.5.3-x86_64.AppImage.sha256
chmod +x install.sh
./install.sh PDFE-0.5.3-x86_64.AppImage --user     # per-user: ~/.local/opt/pdfe, pdfe in ~/.local/bin
./install.sh PDFE-0.5.3-x86_64.AppImage --system   # all users: /opt/pdfe, pdfe in /usr/local/bin (asks for sudo)
```

The installer:

- installs the runtime libraries the AppImage leaves to the host;
- places the AppImage;
- puts `pdfe` on the PATH;
- adds a menu entry that opens PDFs.

It installs only from the local file you downloaded and never downloads anything itself. Running it again is safe. See `./install.sh --help`.

**Any distribution: run the AppImage directly**

```
chmod +x PDFE-0.5.3-x86_64.AppImage
./PDFE-0.5.3-x86_64.AppImage
```
