# P11-BUG-1 RESOLVED (pipeline b3f19d72 phase-5) — root cause was a
#                  Page-reference leak in
#                  MainWindow::onApplyRedactions
#                  (src/ui/MainWindow.cpp:6886).  After
#                  redactionManager_->applyAllRedactions() mutated each
#                  affected page's content stream in memory,
#                  Document::save() called fz_drop_document to release
#                  the file lock, but toolPage_ (still set by the active
#                  redaction tool's setPage(page) flow) plus any held
#                  entries in commandPages_ each carried one
#                  fz_keep_document refcount (MuPDF
#                  source/fitz/document.c:1082 — fz_load_page calls
#                  fz_keep_document on the source doc).  Drop refs were
#                  not reaching zero; the file stream stayed open;
#                  std::filesystem::remove(path) inside Document::save
#                  failed with "The process cannot access the file
#                  because it is being used by another process"; the
#                  save threw before the rename step.  The catch block
#                  in onApplyRedactions surfaced the failure via the
#                  "Redaction Save Error" QMessageBox, but
#                  _wait_apply_completes accepts that dialog as
#                  apply-completed for resilience reasons (it can also
#                  fire on QPDF-rewrite-only failures), so the test
#                  proceeded to capture canvas pixels from a fresh
#                  PDFESession opening the *unchanged* on-disk file —
#                  hence SSIM=1.0000 vs the pre-redact reference.  The
#                  in-memory test test_apply_all_redactions_blanks_
#                  marked_area passed because openFile() inside the
#                  same session re-read the SAME pre-redact bytes but
#                  pdf_redact_page had also been called again on top of
#                  them (the test compares post-apply canvas to
#                  pre-mark canvas, both rendered live).  Fix: before
#                  Document::save() runs, clearCurrentTool() on the
#                  canvas, cancelAll()+waitForDone() on the tile
#                  renderer, invalidateAll() on the tile cache,
#                  reset() toolPage_, clear() commandPages_, and clear()
#                  undoManager_ — all five together drive the
#                  fz_document refcount back to 1 so the subsequent
#                  fz_drop_document inside save() actually closes the
#                  file stream and the remove+rename succeeds.
#                  Diagnostic confirmation: saved-file size shrank from
#                  2943 → 2831 bytes, page-0 extracted text from 220
#                  chars → 0 chars, pixel-diff bbox (0, 30, 612, 419).
#                  Test test_redaction_visible_after_save_reopen
#                  un-xfailed and passes.
